Caso 03

Textilandia

Sistema empresarial y productivo · Terminado

Un negocio textil no puede tener la producción en una planilla, el stock en otra y los pedidos en la cabeza de alguien. Hacía falta un solo flujo.

.NET C# SQL Server

Contexto

Textilandia opera producción textil: materiales, pedidos y stock que cambian en el mismo día. El oficio ya existía. Lo que no existía era un sistema que uniera esas piezas sin pedirle al operador que reconstruya el estado a mano.

Problema

Cuando producción, inventario y pedidos viven en islas, se fabrica a ciegas: se promete lo que no hay, se compra de más o se pierde el rastro de un pedido. El costo no es solo desorden; es decidir tarde.

Mi participación

Participé en el desarrollo de un sistema empresarial .NET / SQL Server para sostener el flujo productivo: de lo que entra a lo que se entrega, con el stock como resultado de ese movimiento, no como una lista que se edita a parte.

Proceso

  • Entender el ciclo del taller: pedido, producción, stock, entrega.
  • Modelar en SQL Server las entidades que el negocio ya usa, no las que un ERP genérico impone.
  • Construir la aplicación en C# / .NET sobre ese modelo.
  • Priorizar las pantallas del día a día por encima de reportes decorativos.

Arquitectura y datos

SQL Server como fuente de verdad. La aplicación .NET cubre la operación. Producción, stock y pedidos se leen del mismo modelo: un movimiento en un módulo tiene que verse en los otros, o el sistema miente.

Resultado

El negocio dejó de operar el ciclo en planillas sueltas. Hay un sistema donde producción, stock y pedidos conviven. El valor está en haber traducido un taller a un flujo que se puede consultar, no reconstruir.

Aprendizajes

En un negocio productivo el usuario no es un analista: si la pantalla no sigue el orden del taller, no se usa. El modelo de datos vale más que agregar campos.
