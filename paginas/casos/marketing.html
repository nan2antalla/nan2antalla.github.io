Caso 05

Módulo de marketing educativo

CRM interno · UTEPSA · Terminado

Admisiones perdía el rastro de las oportunidades. Un módulo para gestionar prospectos, seguimiento y reportes — sobre el mismo stack que el resto de los sistemas internos.

Blazor .NET SQL Server

Contexto

En UTEPSA, marketing y admisiones trabajan con personas que todavía no son estudiantes: consultas, ferias, campañas. Ese pipeline no puede vivir en una hoja compartida si el resto de la institución ya opera sobre SQL Server.

Problema

Sin un CRM interno, la oportunidad se pierde entre un mensaje, una llamada y un olvido. No hay seguimiento común ni una lectura de qué campaña rinde. El dato existe; no está donde el equipo lo puede trabajar al día siguiente.

Mi participación

Como asistente de programación TI participé en el desarrollo del módulo sobre Blazor y SQL Server: captura de prospectos, seguimiento y reportes para que admisiones vea el embudo, no una lista muerta.

Proceso

  • Traducir el flujo real de admisiones a estados que un operador pueda actualizar.
  • Persistir prospectos y movimientos en SQL Server, no en archivos sueltos.
  • Construir las pantallas en Blazor para carga diaria y para la lectura de reportes.
  • Priorizar seguimiento y visibilidad por encima de un tablero bonito.

Arquitectura y datos

Blazor en el frente. SQL Server como fuente de verdad: persona, origen, estado, seguimiento. Los reportes leen ese modelo. No hay una base “de marketing” aparte de la institucional si se puede evitar.

Resultado

Admisiones tiene un lugar donde la oportunidad no se evapora: se registra, se sigue y se reporta. Para la universidad es continuidad; para mí, un CRM que se parece al negocio educativo, no a un producto genérico de ventas.

Aprendizajes

Un CRM interno fracasa si pide más campos de los que el equipo va a llenar. El estado de la oportunidad tiene que caber en el día de trabajo. Este caso espera capturas (sin datos de postulantes) cuando se puedan extraer.
