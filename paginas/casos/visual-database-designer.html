Caso 01

Visual Database Designer

Editor visual · en el navegador · repositorio público

Editor visual de bases de datos relacionales: modelas el esquema en un lienzo, agrupas por unidad de negocio y exportas SQL, JSON o una imagen del diagrama.

Next.js React TypeScript React Flow Zustand Tailwind
Ver en GitHub

Contexto

Diseñar un esquema relacional suele empezar en un editor de texto o en un diagrama estático. Ni el SQL suelto ni una captura sirven para iterar con un equipo. Hacía falta una herramienta que viva en el navegador, sin backend, y que el modelo se pueda ver, editar y exportar.

Problema

Pasar de “tengo el modelo en la cabeza / en un SQL suelto” a un diagrama editable, compartible y exportable. Útil para documentar, explicar a un equipo o partir de un script existente.

Mi participación

Diseño e implementación de extremo a extremo: el dominio del esquema, los comandos con historial, el lienzo, importación y exportación, y pruebas unitarias y E2E.

Qué hace

  • Tablas, columnas, PK, nulos, tipos y color en un lienzo infinito.
  • Relaciones 1:1, 1:N y N:M: arrastras entre campos; las líneas se enrutan solas y, si se cruzan, una pasa por un puente gráfico.
  • Contenedores por dominio, panel de capas e inspector de propiedades.
  • Importar SQL (CREATE TABLE y FK) y JSON; exportar JSON, SQL (PostgreSQL, MySQL, SQL Server, Oracle) y PNG/SVG.
  • Deshacer/rehacer, atajos, tutorial por pasos y temas visuales.
  • Autoguardado en el navegador. No hay servidor ni cuenta.

Arquitectura

Next.js + React en el cliente. React Flow para el lienzo, Zustand para el estado, un historial de comandos para deshacer. Vitest cubre el dominio; Playwright, los flujos de punta a punta. La persistencia es localStorage: el diagrama no sale del navegador hasta que lo exportas.

Resultado

El código está en GitHub: se puede clonar, revisar y correr en local con npm run dev. El producto vive en el cliente; todavía no hay una demo desplegada de esta app.

Aprendizajes

El lienzo no perdona un modelo de datos flojo: si el comando no es reversible, el deshacer se rompe. El enrutado de aristas y los puentes importan más de lo que parece: son la diferencia entre un diagrama legible y un ovillo. A futuro: compartir un esquema por enlace y más dialectos si el uso lo pide.
