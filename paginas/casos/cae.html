Caso 02

CAE — Control de asistencia

Sistema empresarial · UTEPSA · Terminado

Las marcaciones biométricas ya se registraban. El problema era que nadie las veía en el momento y en el lugar donde importaban: la entrada.

.NET C# SQL Server ZKTeco

Contexto

En UTEPSA el control de asistencia depende de dispositivos biométricos ZKTeco en molinetes. El dato existía en el hardware y, en parte, en base de datos. Lo que no existía era una lectura inmediata para quien entra, para seguridad y para operación del campus.

Problema

Sin una capa de visualización en tiempo real, la marcación era un evento opaco: se tocaba el lector y el resto quedaba en un log. Eso genera filas, dudas (“¿me marcó?”) y un hueco entre el dispositivo físico y el sistema institucional.

Mi participación

Como asistente de programación TI participé en el desarrollo de la captura, la persistencia y la pantalla que se muestra en los molinetes. El trabajo cruza hardware, base de datos y una interfaz que tiene que leerse a distancia, no en un monitor de escritorio.

Proceso

  • Entender el flujo real en portería: persona, dispositivo, molinete, pantalla.
  • Integrar el SDK / protocolo de ZKTeco para obtener la marcación cuando ocurre.
  • Guardar y consultar en SQL Server sin bloquear la lectura en vivo.
  • Diseñar una vista de alto contraste, tipografía grande y estado claro (ok / error / espera).

Arquitectura y datos

Dispositivo biométrico → servicio .NET que recibe el evento → SQL Server como fuente de verdad → aplicación de visualización en las pantallas del acceso. El modelo de datos cubre persona, marcación, dispositivo y el estado que la pantalla necesita pintar en el segundo siguiente.

Resultado

La asistencia dejó de ser solo un registro posterior. En el molinete se ve la marcación en el momento. Para la universidad eso significa menos fricción en el acceso y un puente real entre el hardware de control y el sistema interno.

Aprendizajes

Integrar hardware obliga a diseñar para el fallo: red caída, dedo mal puesto, dispositivo desfasado. La interfaz no es un dashboard: es una señal. Si no se entiende en un segundo, no sirve. A futuro: más telemetría de dispositivos y una vista de operación para quien administra los accesos, no solo para quien pasa.
