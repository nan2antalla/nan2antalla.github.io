Caso 06

Dashboard de gerencia

Ingresos y análisis · UTEPSA · Terminado

Los datos ya estaban en la base. Gerencia necesitaba ver cuánto entra, de dónde viene y qué partes generan más ingreso — no exportar a Excel para enterarse al mes siguiente.

Blazor C# .NET SQL Server

Contexto

En UTEPSA la operación ya deja rastro en SQL Server. Lo que no existía era una lectura para gerencia: ingresos, origen de esos ingresos y qué áreas pesan más. El análisis tenía que salir del mismo dato, no de una planilla paralela.

Problema

Sin un dashboard, “cómo vamos” es una conversación. No se ve de dónde viene el ingreso ni qué parte del negocio lo sostiene. El número suelto no sirve para decidir; hace falta el origen y la comparación.

Mi participación

Como asistente de programación TI desarrollé la página de dashboard para gerencia en Blazor y .NET: ingresos, de dónde vienen, qué partes generan más y el análisis de datos en general.

Proceso

  • Leer el modelo que ya existe; no inventar una verdad nueva.
  • Mostrar ingreso, origen y las partes de mayor recaudación.
  • Comparar gestiones para que el número tenga contexto.
  • Priorizar la lectura a distancia: el indicador, la variación, la pregunta que responde.

Arquitectura y datos

SQL Server como fuente. Blazor pinta la lectura. El dashboard no crea el ingreso: lo agrega y lo corta por origen y por área. Si el número no sale de la operación, no entra al tablero.

Resultado

Gerencia tiene una pantalla para ver el ingreso y su composición. El análisis deja de ser un export. Para mí, el valor está en haber traducido preguntas de negocio —cuánto, de dónde, qué pesa— a consultas y a una interfaz que se entiende en una pasada.

Aprendizajes

Un dashboard de gerencia no es un collage de gráficos. Cada tarjeta tiene que responder una pregunta. Si no se puede decir en una frase qué muestra, sobra.
